Set up the initial development environment and create a clean foundation for the project.

## What I Did

- Cloned the repository into VS Code.
- Verified that Git was correctly connected to the GitHub repository.
- Confirmed that Python 3.12.10 was installed and available.
- Created a Python virtual environment using venv.
- Activated the virtual environment in PowerShell.
- Configured VS Code to use the virtual environment's Python interpreter.
- Created the initial project structure.
- Added a .gitignore file to prevent the virtual environment, Python cache files, and environment variables from being committed to Git.
- Created the initial src/app package.
- Created the tests and documentation directories.
- Created the first Git commit and pushed it to GitHub.

## What I Learned

- A Python virtual environment allows a project to have its own isolated dependencies instead of relying on the system-wide Python environment.
- VS Code needs to be configured to use the correct Python interpreter for the project.
Git tracks files rather than empty directories, which is why empty directories such as tests and docs/dev-log do not appear in git status yet.
- A .gitignore file is important for preventing files such as .venv and .env from being accidentally committed.
- Making small Git commits throughout development provides a history of how the project was built.

## Problems I Encountered

- I initially needed to verify which Python installation and pip were being used by the project. I also needed to make sure VS Code was using the project's virtual environment rather than the system Python installation.

## How I Solved Them

- I created a .venv environment inside the project and selected .venv\Scripts\python.exe as the Python interpreter in VS Code. I then verified the interpreter using:

    python -c "import sys; print(sys.executable)"

The output confirmed that Python was being executed from the project's .venv directory.
